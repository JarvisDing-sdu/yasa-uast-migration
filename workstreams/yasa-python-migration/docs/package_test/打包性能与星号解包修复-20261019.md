## 1. 测试口径

## 2. 性能根因的受控验证

同机 Node v22.22.1，相同源码、相同 606 文件、相同规则、workerCount=1，仅改变 `--expose-gc`：

| 配置 | symbolInterpretMs | totalTimeMs | findings | entrypoints |
| --- | ---: | ---: | ---: | ---: |
| 不开启显式 GC | 2531 | 6519 | 332 | 1295 |
| 开启显式 GC | 50895 | 54743 | 332 | 1295 |

完整 SARIF 归一化比较：identityEqual=true、normalizedResultsEqual=true、oldOnly/newOnly 均为空。分析阶段慢约 20.1 倍。这是单次对照，非多轮统计结果，也非新打包二进制验收。

代码路径：build.sh 把 expose-gc 烘焙进 pkg 产物；entrypoint-executor.ts 在每个入口结束时调用 global.gc()，performance-tracker.ts 在阶段内存统计中也会调用。共 1295 个入口，主动 GC 把诊断测量变成大量停顿。普通源码启动不暴露 global.gc，因此没有这项开销。

最小修复：仅从默认 pkg options 移除 expose-gc，保留 max-old-space-size=11264。自动垃圾回收仍然正常工作。主动开启 GC 的诊断运行仍可能很慢。不能由此认定所有 pkg 性能问题都已解决，也不能仅凭 Failed to make bytecode 警告归因于 JIT。

复现命令（在 engine 目录）：

```bash
node --import tsx src/main.ts test/python/benchmarks/sast-python3/case --ruleConfigFile test/python/rule_config_xast_python3.json --analyzer PythonAnalyzer --checkerIds taint_flow_test --workerCount 1 --report /tmp/yasa-gc-check/no-gc
node --expose-gc --import tsx src/main.ts test/python/benchmarks/sast-python3/case --ruleConfigFile test/python/rule_config_xast_python3.json --analyzer PythonAnalyzer --checkerIds taint_flow_test --workerCount 1 --report /tmp/yasa-gc-check/with-gc
```

本次原始日志、scan_summary.json、report.sarif 暂存 `/tmp/yasa-gc-check/`，不是已上传的持久归档。

## 3. 星号解包修复

tree-sitter-python 0.25.0 对不带括号的 tuple 星号展开存在语法缺口；带括号的等价形式可以解析。源代码路径也能复现，因此不是 pkg 独有的 bug。

未改 UAST 格式、未关闭语法错误检查、未引入 Python 外部进程。仅在原解析失败时，对满足条件的星号 token 作同宽占位重试；新树必须完全无错误，且替换点必须对应 expression_list 的直接元素。Visitor 恢复 DereferenceExpression，包含整个展开表达式，避免把 `*[None] * 3` 错误理解为先展开再乘。字符串、注释、赋值左侧星号 pattern 不修改，双星号不参与此兼容处理。

回归包含队员报告的四类最小表达式：生成器展开、多个展开加乘法、括号内乘法展开、赋值右侧空列表展开。逐一与加括号版本比较归一化 UAST；另检查 Unicode、普通乘法和非法语法拒绝。

验证：解析器 npm test 12 通过、5 跳过（未设置 PYTHON_UAST_ORACLE）；直接调用 TypeScript 编译器通过。发现本机 parser-Python/node_modules/.bin/tsc 是空文件，故没有把 npm run build 的退出成功当成构建证据，实际使用 `node node_modules/typescript/bin/tsc` 编译，并编译到 engine 的本地 parser 包副本以进行集成验证。

修复后的 parser 已实际编译到 engine 本地依赖副本，再跑 606 文件：332 findings，symbolInterpretMs=2601，totalTimeMs=6279；与修复前 no-gc 的完整 SARIF 归一化比较一致。产物在 `/tmp/yasa-gc-check/verified-fixed-parser/`。
