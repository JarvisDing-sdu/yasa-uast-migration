# C/C++ 混合扫描完善记录（2026-11-09）

当前为本地开发分支 `feat/c-cpp-scan`，只有验收通过后才发布。原 C、C++ 模式和历史基线保持独立；本次结果不能替代原始基线。

## 实现范围

新增显式入口 `--language c-cpp`。必须提供实际 `compile_commands.json` 和显式构建选择 `--buildProfile`；每条选择含编译记录 `entryId` 和链接范围 `domainId`。不根据后缀猜头文件、不同时试两种语言取并集、不把整个仓库当成一个程序。同一 `.h` 按包含它的编译单元分别预处理，保留宏、include 路径、语言、标准、目标和环境上下文。

编译器负责完整预处理，原始 `.i/.ii`、行标记、依赖与内容摘要、编译器版本和 argv 均保留。Clang JSON AST 只提供真实声明、引用、名称改编和有效语言链接等辅助信息；函数体仍交给原来的 C / C++ parser，通过新增 `parsePreprocessed` 入口转换为 UAST。该入口不重复预处理。

当前混合模式需要 Clang。编译记录读取器可识别 GCC 驱动，但实际 GCC 预处理后的声明辅助分析尚未完成，正式流程明确失败，不能声称支持 GCC。系统中名为 gcc 的 Apple Clang 按实际版本识别。

## 系统头处理

完整系统头保留在原始产物中。分析器使用真实 ABI 标识关联库模型，项目函数与库模型同名时，以实际声明和项目定义为准。被项目实际引用、没有显式模型的普通系统头包装函数会保留函数体，并递归保留其调用的包装函数。不能只删掉系统实现就声称已分析其语义。

尚不支持的模板、类、构造、引用等语义产生明确的 partial / failure 诊断；不能报告为完整成功。系统头中尚未支持的动态全局初始化也必须产生 partial，不能因为初始化代码位于系统头就跳过诊断。其完整语义、GCC 兼容和更完整的 C++ 对象模型不在当前已验证能力内。

## 符号与隔离

函数和全局变量使用编译器声明身份与真实链接名称，内部链接额外包含编译单元，独立目标额外包含链接范围。正确区分 C ABI、普通 C++ 同名函数、命名空间中的 extern C、匿名命名空间和函数局部静态变量。重复外部定义产生冲突诊断，不采用先到先得。

每个链接范围在独立工作进程分析，避免旧全局配置串用。旧 C、C++ 入口继续走原流程。混合模式的直接调用图由编译器绑定后的 UAST 建立，间接调用边由既有解释过程补充；这不等于全部 C++ 间接调用都已解决。

内部 UAST 保留每个编译单元的生成坐标，避免跨上下文节点身份冲突；额外保存原文件和行号。SARIF、调用图展示映射回原文件及行号；预处理行标记不能证明原始 token 列号，因此不伪造列号。

## 验收口径

冻结 gold 在新增入口前完成，27 个夹具全部先真实编译和链接，不运行危险样例。包含 13 个危险例、13 个安全对照、1 个缺失生成头文件的失败案例，覆盖跨语言参数、返回值、指针写回、回调、语言链接、同名目标隔离、头文件宏和静态存储。

`mixed_regression.py` 独立运行和复评分，保留报告、日志、编译链接证明、输入与产物校验值。固定用例分数不外推为真实项目准确率。失败或部分扫描不计入正常成功通过。

原有回归包括 parser-C 原 72 项、Engine C 原 112 项、sast-C 逐例、2,451 个 UAST 摘要、4 组 Juliet C、curl 完整评分，以及 CPP 原有与 M1 修复测试、8 组 Juliet CPP；本次所有原始失败试验也保留。

真实目标使用 zlib 提交 `99623ef7097352da7993ba614161fd6a311e046e`。库以 C 编译；上游未修改的 `test/example.c` 本轮明确以 `-x c++ -std=c++17` 编译并链接实际 C 库，链接映射选出 14 个 C 单元和 1 个 C++ 单元。这是本轮选择的 C++ 编译配置，不称为上游默认 C++ 构建。另有原生 iostream3 试验，完整系统头 AST 和失败诊断均保留。真实项目没有完整漏洞 gold，不报真实漏洞准召率。

## 真实目标性能定位

`report-v4` 的15个单元全部解析后，工作进程在主入口超过600秒，保留失败manifest。独立诊断重放 `profile-v5` 的原始V8 CPU采样及暂停栈显示：公共分支后处理调用通用AST遍历时，进入CBranch包装节点的 `results[].before` 运行时作用域快照，反复走完整污点/全局变量对象图。此处不是解析失败。

仅在新增 CFamilyAnalyzer 中解开 CBranch 的语法body后调用旧分支后处理，不改原C/CPP路径。新增回归明确禁止访问运行时快照，并核对真实return仍能影响分支终止判定。正式结果另写 `report-v6`，不覆盖之前的超时记录。诊断重放在采样完成后显式结束，不计为通过。
