> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 记录 C 回归基线（M0），并让 `--language cpp` 能扫描 C++ 项目中的 C 子集和命名空间代码、跑通 Juliet C++ 01 号变体（M1），C 的行为完全不变。

**Architecture:** parser-C 增加一个不改变 C 输出的扩展点（可替换 tree-sitter 语言、节点处理扩展表、对外导出内部函数），新包 parser-CPP 基于 tree-sitter-cpp 复用它。Engine 新增 `cpp` 语言和 `CppAnalyzer extends CAnalyzer`；`CAnalyzer` 只做提取可覆盖方法的无行为变化重构。规则、checker、checker 包均为 C++ 单独新建。

**Tech Stack:** TypeScript、web-tree-sitter 0.26.x、tree-sitter-cpp 0.23.4、mocha + tsx、Python 3（评分脚本）、clang（Juliet 构建配置参考）。

**Spec:** `workstreams/yasa-cpp-extension/docs/2026-11-08-cpp-support-design.md`

## Global Constraints

- C 回归基线（设计 §4）每个任务结束都不得变化：parser-C 69/69（加上本计划新增的测试）；Engine `npm run test-c` 111/111；sast-c TP 110 / FN 0 / TN 54 / FP 0；C 语料 UAST 输出逐字节一致；Juliet C 与验收报告一致；curl 调用图评分不变。

- `cpp` 模式扫描 `.cpp .cc .cxx .c++ .hpp .hh .hxx .h .inl`，不扫描 `.c`；`c` 模式的扩展名和行为不变。

## Review Focus

1. 同名函数在不同命名空间中（Juliet 每个用例都有 `namespace X { void bad() }`）：一次扫描多个用例时不得合并，污点只在本命名空间内传递。→ Task 5 测试 `namespaces_do_not_merge_T/_F`。
2. 宏展开结果含 C++ 语法（如 `#define RUN std::system`）：宏展开必须用 C++ 语法解析，不能退回 C。→ Task 2 测试 `uses the caller's tree-sitter parser for macro expansion`，Task 4 测试 `expands a macro containing a qualified name`。
3. 头文件中 `#ifdef __cplusplus` / `extern "C"`：cpp 模式走 C++ 分支，c 模式结果不变。→ Task 3 测试 `defines __cplusplus`，Task 1 快照覆盖 c 模式。
4. 混合项目用 `--language cpp` 扫描：`.c` 不进入分析、`.h` 按 C++ 解析、不崩溃。→ Task 5 测试 `cpp mode ignores .c files and parses .h as C++`。
5. 含无法解析的 C++ 构造（重模板）的文件：记录 `parseErrors`，其余函数保留，不抛异常。→ Task 4 测试 `keeps functions around unparseable template code`。
