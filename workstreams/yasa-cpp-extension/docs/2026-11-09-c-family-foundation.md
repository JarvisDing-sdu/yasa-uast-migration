# C/C++ 混合扫描发布前基础修复

2026-11-09。本轮完成原合并计划的第一阶段，工作分支为 feat/c-family-foundation。正式混合命令的集成与完整系统头处理继续作为发布前待办。首次试验、原 M1 报告和冻结结果保留。

## 已修复

- 单独扫描 .h 时，显式语言、配置文件语言和显式 analyzer 能在 AST 导出及正常分析入口生效。无语言参数继续推断为 C。连续 AST 导出按每份文件推断，自动推断值在导出后恢复。解析器初始化失败时也恢复，调用者直接设置的 Config.language 得以保留。
- namespace N { using ::system; } 后调用 N::system 的真实库身份可以追溯；getenv source 同样适用。传递 using、using-directive 和循环导入有回归用例。调用交给既有 C 模型之前保留解析出的函数身份。
- 自定义命名空间中的同名函数继续执行自己的实现。相对 std 查找先核对当前命名空间的声明，防止把 X::std::system 误认作全局标准库。C++ parser 给函数原型保留 namespace/qualifiedName，Engine 使用该信息解析。
- 两个不同函数即使写在同一行，也能通过列范围区分。调用图的根入口筛选和反向查找入口均已修复，安全用例还断言存在有效分析入口，防止以跳过分析得到零告警。

独立审阅复现了原 M1 漏报及首版补丁的边界问题，问题对应的回归均确认先失败后通过。最终定向复核确认同一行危险链检出、嵌套 std 安全例有有效入口且无误报、连续导出及初始化故障恢复正确。完整历史审阅报告另存于原始证据。
